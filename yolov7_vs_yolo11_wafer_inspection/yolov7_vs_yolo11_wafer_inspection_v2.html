YOLOv7 與 YOLO11 實例分割（Instance Segmentation）技術特色比較說明

給 QC 產線主管與製程／設備工程師：AOI 抓到瑕疵之後，接下來要做的是逐顆標出瑕疵的輪廓、量面積與長度、判斷類別，並把結果寫回 MES 與 SPC。本文比較兩代 YOLO 模型在這件事上的差異，以及導入時要注意的地方。

為什麼用實例分割 瑕疵類型對應 技術亮點 功能比較 QC 指標影響 選型建議 導入步驟

01為什麼晶圓檢測需要「實例分割」

只畫框、只分類還不夠：品質判定依據的是瑕疵的大小、形狀和位置。

物件偵測（Bounding Box）

告訴你「哪裡有瑕疵」。但一條斜向刮痕的外框可能覆蓋大半顆 die，面積會被嚴重高估，容易造成過殺。

語意分割（Semantic）

標出所有瑕疵像素，但相鄰或重疊的瑕疵會黏成一塊，無法逐顆計數，也就無法統計 defect density。

實例分割（Instance）

每一顆瑕疵都有自己的像素級輪廓、類別與信心分數。可直接換算面積、長度、寬度、與 die 邊界的距離，再對照規格做 Pass/Fail 判定。

對產線的意義：判定規則可以從「人眼看有沒有」變成「量化數值是否超出規格」，例如「刮痕長度 > 50 µm 判 NG」「微粒面積 < 3 px² 視為雜訊」。判定標準一致，也能追溯，方便寫入 SPC 管制圖。

02常見晶圓瑕疵與模型能力對應

不同瑕疵型態對模型的要求不同，這也是兩代模型拉開差距的地方。

瑕疵類型 影像特徵 技術難點 對模型的需求
微粒（Particle） 數個到數十個像素的小點 極小目標，容易被當成背景雜訊 小物件敏感度、高解析輸入或切圖（tiling）推論
刮痕（Scratch） 細長、方向任意、可能斷續 長寬比極端，預設 anchor 形狀難以匹配 Anchor-free 設計、精準的遮罩邊界，必要時搭配旋轉框（OBB）
邊緣崩缺（Edge Chipping / Crack） 出現在晶圓邊緣，形狀不規則 背景是晶圓外緣，對比度變化大 對不規則輪廓的遮罩品質
圖形缺陷（Pattern Defect） 線路斷線、短路、橋接 正常圖形重複且複雜，瑕疵僅是局部差異 上下文理解（注意力機制）、低誤報
殘留／污漬（Residue / Stain） 低對比、邊界模糊的區塊 邊界不清，人工標註也常不一致 對低對比特徵的辨識，以及一致的標註規範

03兩代模型的技術亮點（用產線語言說明）

兩代模型強化的方向不同：YOLOv7 主要改良訓練方法，YOLO11 則把重點放在輕量化與工程落地。

YOLOv72022 · 中研院團隊

  • E-ELAN 骨幹網路：網路加深時仍能穩定學習。→ 在瑕疵樣本有限時，模型也比較不容易訓練失敗。
  • 重參數化卷積（RepConv）：訓練時使用多分支結構，部署時合併成單一卷積。→ 準確度提升，推論速度不受影響。
  • 主／輔助頭標籤分配（Lead-guided Assignment）：以輔助頭加強中間層的學習。→ 提高對模糊瑕疵的召回率。
  • 實例分割為「外掛」：以 BlendMask 或 prototype mask 分支實作，需切換程式碼分支並修改設定檔。
  • Anchor-based：預設框形狀以 COCO 一般物件為準，處理細長刮痕通常要重新聚類 anchor。

YOLO112024 · Ultralytics

  • C3k2 模組：以較小卷積核組成的輕量模組。→ 同等準確度下，參數量與運算量更少，單機可處理更多影像。
  • C2PSA 空間注意力：讓模型聚焦在影像中「不一樣的地方」。→ 適合在重複的電路圖形中找出局部異常，對小微粒與低對比瑕疵也有幫助。
  • Anchor-free 解耦偵測頭：不預設框形狀，分類與定位分開學習。→ 細長刮痕、不規則崩缺都不需要額外調 anchor。
  • 原生實例分割：n / s / m / l / x 五種規模的 -seg 模型，可依產線節拍與硬體選擇。
  • 一鍵匯出 TensorRT / ONNX / OpenVINO：從訓練到上線 GPU 推論的流程短，方便整合到既有 AOI 機台或邊緣 GPU 主機。

04功能與導入面比較

對工廠來說，除了模型準確度，還要評估能不能長期維護、能不能接上既有系統。

評估面向 YOLOv7 YOLO11
支援任務 偵測、姿態、實例分割，分散在不同程式分支 偵測、實例分割、分類、旋轉框（OBB）、姿態、追蹤，使用同一套 API
晶圓檢測延伸應用 以分割為主，其他任務需自行整合 分割量測瑕疵、OBB 標出刮痕方向、分類模型做 die 級判定，可在同一框架內組合
訓練與調參門檻 研究型程式碼，需熟悉 PyTorch 與設定檔 一行指令即可訓練，工程師較易接手
部署到產線 GPU ONNX／TensorRT 轉換需自行處理或依賴社群腳本 內建 export，可直接輸出 TensorRT（FP16／INT8）
長期維護 原團隊已轉往後續研究，更新頻率低 持續維護，文件與社群資源豐富
授權（法務必看） GPL-3.0修改後散布須開放原始碼 AGPL-3.0透過網路提供服務也適用開源義務；商業封閉部署通常需購買 Ultralytics 企業授權

05對 QC 關鍵指標的影響

把模型特性換算成產線主管關心的指標（實際幅度依產品、光學條件與樣本量而定）。

漏檢率 ↓
Escape Rate

YOLO11 的注意力機制與 anchor-free 設計提升了對小微粒與細刮痕的召回率，減少瑕疵流到下游。

過殺率 ↓
Overkill Rate

像素級面積與長度量測取代外框估算，避免把小瑕疵誤判為 NG，減少良品被報廢或送去人工複判。

檢測節拍 ↑
UPH / Takt Time

同等準確度下模型更輕量，加上 TensorRT 加速，單台 GPU 可負擔更多機台或更高解析度影像。

人工複判 ↓
Review Loading

判定一致且可量化，人工只需複判信心分數落在灰色地帶的案例，釋放 QC 人力。

工程提醒：晶圓影像常是高解析度大圖（數千至上萬像素），微粒可能只有幾個像素。無論選哪一代模型，都建議採用切圖推論（tiling／SAHI），並針對瑕疵樣本少、類別不平衡的情況規劃資料增強與主動學習（active learning）流程。

06選型建議

依產線現況決定，沒有一體適用的答案。

建議多數新專案選 YOLO11-seg

  • 新建 AOI 產線或首次導入 AI 瑕疵檢測
  • 需要同時處理微粒、刮痕、崩缺等多種瑕疵
  • 產線節拍要求高，需要 TensorRT 加速的線上全檢
  • 工程團隊希望自行持續再訓練、快速迭代
  • 建議起點：YOLO11m-seg 做 POC，驗證後再依節拍縮到 s 或放大到 l
  • 商業封閉部署前請先確認授權方案

特定情境保留或選用 YOLOv7

  • 既有檢測系統已以 YOLOv7 建置且運作穩定，遷移與重新驗證成本高
  • 研發單位要深入修改模型結構或標籤分配機制
  • 授權策略上偏好 GPL-3.0
  • 建議：可並行用 YOLO11 做 A/B 測試，以同一批驗證集比較漏檢與過殺，再決定是否升級
值得關注：Ultralytics 於 2025 年推出 YOLO26，主打免 NMS 後處理的端到端推論，可進一步降低延遲並簡化邊緣部署。新專案可一併納入評估。

07建議導入步驟

從小範圍驗證開始，用數據決定是否擴大導入。

  1. 定義瑕疵類別與判定規格
    由 QC 與製程共同確定瑕疵類別、NG 規格（面積、長度、位置），並建立標註規範，減少標註者之間的差異。
    產出：瑕疵定義書、標註 SOP
  2. 收集與標註樣本
    從 AOI 與 Review 站收集影像，以多邊形標出瑕疵輪廓；稀有瑕疵要特別補樣，並保留正常樣本做為對照。
    產出：訓練集與驗證集（驗證集固定不動，作為所有模型的比較基準）
  3. POC 模型訓練與驗證
    以 YOLO11m-seg 為基準，必要時與 YOLOv7-seg 對照；依瑕疵類別分別看召回率、精確率與遮罩品質。
    產出：漏檢率、過殺率、推論速度報告
  4. 門檻調校與產線試跑
    與 QC 共同調整信心門檻與尺寸規則，先以「AI 建議、人工確認」的影子模式（shadow mode）上線比對。
    產出：上線判定規則、與人工判定的一致性數據
  5. 正式部署與系統整合
    匯出 TensorRT 引擎部署到產線 GPU 伺服器或邊緣主機，檢測結果（類別、座標、面積、wafer map）寫回 MES 與 SPC。
    產出：線上檢測服務、wafer map 報表
  6. 持續學習與模型維運
    收集誤判與新型瑕疵樣本，定期再訓練並做版本管理；製程或機台變更時，先回歸驗證再上線。
    產出：模型版本紀錄、定期效能報告
